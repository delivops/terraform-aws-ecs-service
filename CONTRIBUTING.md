# Contributing

## Requirements

Terraform `>= 1.9` (declared in `versions.tf`; required for validation rules
that reference other input variables) and the AWS provider `>= 5.0`. No AWS
credentials are needed for `fmt` or `validate`.

## Before opening a pull request

The repository has three independent Terraform roots. CI checks all of them, so
run the same commands locally:

```bash
terraform fmt -recursive

terraform init -backend=false && terraform validate

cd examples     && terraform init -backend=false && terraform validate && cd ..
cd examples/gpu && terraform init -backend=false && terraform validate && cd ../..
```

`examples/` and `examples/gpu/` are separate roots — a change to the module's
variables can break an example without breaking the module.

## Releases

Merging to `main` cuts a release automatically from the squash-commit message.
The bump follows conventional commits:

| Squash commit prefix | Bump |
|---|---|
| `fix:`, `refactor:`, `docs:`, `chore:` | patch |
| `feat:` | minor |
| `feat!:` or a `BREAKING CHANGE:` footer | major |

**The default is a patch bump.** A breaking change merged without `!` or a
`BREAKING CHANGE:` footer ships as a patch, and consumers on a `~>` constraint
pick it up automatically. Check the prefix before merging anything that removes
a variable or output, changes a default, or destroys a resource.

Changes confined to `README.md`, `.github/**`, or `examples/**` do not cut a
release.

## Documentation

The input and output tables in `README.md` are generated by `terraform-docs` in
CI and pushed back to the branch. Edit variable and output `description` fields
rather than the generated tables; prose outside the `BEGIN_TF_DOCS` markers is
maintained by hand.
