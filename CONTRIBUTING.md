# Contributing

Thanks for contributing to `terraform-aws-ecs-service`.

## Development

Requirements: Terraform `>= 1.9`.

Before opening a pull request:

```bash
# Format all files (module + examples)
terraform fmt -recursive

# Validate the module
terraform init -backend=false
terraform validate

# Validate the examples (each is its own root)
cd examples      && terraform init -backend=false && terraform validate && cd ..
cd examples/gpu  && terraform init -backend=false && terraform validate && cd ../..
```

## Documentation

The `## Requirements` … `## Outputs` section of `README.md` is generated by
[terraform-docs](https://terraform-docs.io/) between the `BEGIN_TF_DOCS` /
`END_TF_DOCS` markers. It is regenerated automatically by the
`.github/workflows/documentation.yaml` workflow — do not hand-edit inside the
markers. Edit the prose above the markers as needed, and give every variable and
output a meaningful `description`.

## Examples

`examples/` is a single Terraform root: shared input variables live once in
`examples/variables.tf`, and each `*-example.tf` file adds module instances.
Keep new examples self-contained within that root (no duplicate `variable`
blocks). `examples/gpu/` is a separate root with its own variables.

## Releases

Merging to `main` triggers `.github/workflows/git-tag.yaml`, which bumps a
semantic-version tag and creates a GitHub release. Use Conventional Commit
prefixes (`feat:`, `fix:`, `chore:`, `feat!:`/`BREAKING CHANGE:` for breaking
changes) so the version bump is correct, and record breaking changes in
`CHANGELOG.md`.
